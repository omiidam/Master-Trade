# Technical debt register

Items **actually remaining** after Phases 5.1–5.10 and 6.1–6.5, with what each one costs and what
has to happen for it to matter.

This register deliberately holds debt, not roadmap. A capability the product intends to build later
is a plan, and plans live in [`risks-and-deferred.md`](./risks-and-deferred.md) and the phase docs. An
entry appears here only when the current state is _already_ worse than it should be, or when
something shipped cannot yet carry the weight it is expected to. Where a genuine deferral has a
trigger — the security and privacy items, TLS termination, the `pg` driver — it is listed in
`risks-and-deferred.md` §6 rather than duplicated here.

`Blocking` means: a next phase that depends on this must do it first. `Non-blocking` means the
Foundation works, and the cost is real but bounded.

## What is deliberately **not** in this register

- **Deferred security work with a known trigger** (TLS termination, trusted-proxy placement, per-route
  rate-limit tiers, audit retention enforcement, incident runbook). Listed in `risks-and-deferred.md`
  §6, because each is correctly deferred rather than accidentally missing.
- **Unbuilt capabilities that are priced and declared** (`backtest.run`, `research.report`,
  `market.structure`, `portfolio.risk`, `memory.export`). These are declarations, not debt: the
  registry says `coming-soon` or `disabled` on screen, and the boot check refuses a build that names
  an unknown analysis type, feature, cost or operation.
- **The prototype interface itself.** Rendering labelled fixtures is the declared scope of Phases
  5.1–5.10 and is stated on screen (`Preview · mock data`), tested, and recorded as risk R18. Debt
  would be rendering mock data _without_ saying so.
